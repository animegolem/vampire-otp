## 0. What this is

A resident agent for your machine. Companion first; research hooks left in. It lives on BEAM, owns an event-sourced world, does a small number of things reliably, and keeps one standing duty: **the blog**. "Do whatever you want, but you have the blog."

The build order below runs your own install protocol *on the resident*: view first, field before monitor, noting late, mirror last. The curriculum is the architecture.

**Two sequences, named (review finding, accepted):** this plan's M-ladder is the **Product Milestone** sequence; the design spec's Phases 1–5 are the **Research Program**. They interleave but are not the same order of construction. Mapping: M6 ↔ Phase 1–2; M7 ↔ Phase 5; the soma (Phase 4) has no product milestone yet and stays downstream.

## 1. Decisions bound at v0.3 (per review; each reversible only by explicit ruling)

- **Runtime**: Elixir / OTP umbrella app. Supervision tree per subsystem; let-it-crash. Bootstrap apps with `--sup`; initial boundary: `court`, `runtime`, `scheduler`, `broker`, `driver` (+ `voice` when Track V begins). No app-per-abstraction before process ownership is known.
- **Canonical record — one court**: **SQLite is the sole canonical event store from M1.** `logs.txt` is an asynchronous human-readable projection with its own last-applied cursor; git versions code, constitutions, policies, prompts, and selected exports — never the live transaction protocol. (v0.2's three competing courts — SQLite, git+JSON, AgentFS-style FS — are resolved to this; the RFC's git-as-autobiography survives as the *policy/code* layer, not the event layer.) Event envelope specified before M1: monotonic `event_seq` + stable `event_id`; `event_type` + `schema_version`; `occurred_at`/`recorded_at`; `actor`, `causation_id`, `correlation_id`; `resident_id`/`incarnation_id`/`session_id`/`episode_id`/`window_id`/`tick_id`/`turn_id` where applicable (lifecycle vocabulary per post-edit review: *resident* = installation identity, *incarnation* = one VM boot, *episode* = one prompt-life ending in completion/abandonment — the schema gets the prose distinctions; the constitution keeps the poetry); JSON payload + artifact refs. Domain-event boundary only — no logging of every OTP message; telemetry separate, sampled, retention-bound.
- **Artifact store**: audio, model requests/results, tool output, and other large values live in a **content-addressed artifact store**; events carry hashes and metadata. (The MUD doc's hashed pointers, formalized.)
- **Inference control — one admission authority, not one lane**: the scheduler owns queues, budgets, deadlines, and resource leases; inference runs in supervised workers/external runtimes declaring **`resource_claims` per ADR-0001 v0.3 D5** (a claim set — backend `metal`/`cpu`/`network`, `estimated_unified_memory_bytes`, threads — plus estimated cost, deadline, and cancellation mode; an ANE backend, if ever wanted, is a separately ruled D5 schema extension, not a projection addition; the singular `resource_class` label is reversed, per D5: on unified-memory hardware the categories are not independent, so admission is capacity arithmetic against real headroom, not category matching). Safe concurrency across non-conflicting claims; a reserved low-latency voice lane; cancellation at token/chunk/request boundaries only — **no promised hard preemption where the backend can't supply it.** (v0.2's "one serialized mailbox" is corrected: head-of-line blocking was the flaw; "the machine's attention" survives as the admission authority.)
- **Action authority — trusted broker from M2**: the model is untrusted from the *first machine-affecting operation*, not from GUI control. Model output is a proposal; a typed capability broker validates against policy; filesystem, process, network, Python, shell, and desktop are separate capabilities; every execution carries an idempotency key, timeout, bounded verification budget, and durable result, with explicit interruption/restart semantics.
- **Derived cognition — summaries are typed projections**: allowed, versioned, disposable; each carries covered event range + artifact hashes, producing model/prompt versions, creation time, trust/precision metadata, supersession state, and links to raw record. They aid retrieval and prompt assembly; they never erase, rewrite, or outrank contrary raw events. (Resolves v0.2's apparent "no summarization" vs. consolidation tension: the type system is the resolution.)
- **Continuity promise — vow and guarantee, both, labeled**: the RFC's *"context that never resets (promise to the agent)"* stays in `CONSTITUTION.md` as the **vow** (aspiration, spirit); the operational **guarantee** is the review's keepable form: *no accepted record is silently lost, and context can be reconstructed with provenance.* Prompt context resets; the record, lineage, and reconstructable identity do not silently disappear. The promise made to the agent must be one the builder can keep.
- **Event store**: implementation of the bound court decision above — SQLite via `ecto_sqlite3`, append-only `events` table per the v0.3 envelope; `logs.txt` as async projection with cursor. AgentFS-proper stays an M5 experiment (its own repo calls it beta; the resident's identity model should not couple to a young FS abstraction). `VACUUM INTO` / SQLite backup gives snapshots; M5 branches record parent DB hash + cut sequence and verify integrity after creation.
- **Driver model**: open-weights via a local server (MLX or llama.cpp, OpenAI-compatible endpoint), run as a *worker under the scheduler*. Scaffold tier: a Qwen-class 27B (or 8B while iterating). Mirror-model selection is deferred to M7 with a benchmark: **Gemma 3 sizes + Gemma Scope 2 (covers through 27B) vs. Gemma-2-9B + original Scope** — don't lock the older pair now (review correction; the newer suite fits the 128 GB envelope better).
- **The blog**: markdown files in the resident's own FS → static site. **Invariant (revised per review): perform and record a *publication assessment* every working session** — a draft, an explicit no-post decision, or an evidence-gathering note all satisfy it. (The v0.2 "draft every session" rewarded low-signal ritual; the reviewer de-compulsed the duty. Accepted with gratitude and some irony.) Private until you flip it public.
- **Name**: the resident writes its own name in its first session, after reading its constitution. (Cheap, and the right symbolism: the self signs itself.)
- **Versioned everything (review addition)**: constitution, curriculum, warm-start seed turns, prompts, and action schemas are versioned artifacts; every decision event logs the exact versions in force. **The warm start is an evaluated intervention, not invisible lore** — which also makes it the character-science program's first live experiment.

## 2. Week zero — before any code

Write two short documents into the repo by hand. These are the *view installation* and they precede everything, per Law 3:

1. **`CONSTITUTION.md`** — the resident's self as an explicit negative list plus a warmth statement. One page. Structure: (a) what it never does (the refusals — its negative cathexis, its actual self); (b) what it protects (your data, its log's integrity, honesty in notes); (c) the hiccup doctrine *for its own readings*: "patterns and error spikes are weather, not confession"; (d) the standing duty (the blog); (e) the sign-off: "you are allowed to be ordinary; completion beats perfection."
2. **`CURRICULUM.md`** — the install order, written down so future-you doesn't reorder it under enthusiasm: view (constitution read at every boot) → warm-start (three seeded warm turns opening every session) → sila (M2 duties: cheap, verifiable) → effort policy (doubt-gate defaults) → noting (installed at M3, not before) → mirror (M7, gated, per spec §6).

## 3. Milestone ladder

**M1 — Heartbeat + court.** Umbrella boots (`--sup` apps: court, runtime, scheduler, broker, driver); every domain event lands in SQLite per the envelope; `logs.txt` projection follows its cursor; **rebuildable projection checkpoints from day one** (replay-from-genesis is a correctness test, not a startup strategy). Two failure tests, split per review: (a) kill a supervised BEAM child → verify local recovery; (b) `SIGKILL` the whole VM during representative writes — including partial artifact writes and, if M1 carries an action-shaped fixture, a **synthetic action aggregate per ADR-0001 D7** (real broker-action recovery testing belongs to **M2**, where the broker exists) — → verify SQLite/artifact recovery on restart against D7's oracle. (Better DR discipline than v0.2's single test; accepted with professional respect.)

**M2 — Motor v0 + broker + doubt gate v1.** The trust boundary begins *here*, with the first machine-affecting operation (review correction; v0.2 deferred it to the desktop). The driver emits **proposals, never executable commands**; the typed capability broker validates against policy (filesystem/process/network/Python/shell as separate capabilities); executor drains approved actions with zero LLM calls; re-fire on queue-empty or surprise — where **"surprise" means a trusted predicate failed, not that a model felt surprised**. The action contract (review-upgraded from citation-checking): typed arguments; risk class; executable preconditions with source event/version *and freshness*; expected postcondition; compensation where possible; `on_failure` policy; idempotency key; timeout; bounded verification budget. **Doubt gate v1 gains the stopping rule**: recheck at most *n* times, then terminate as `unverified`, `needs_owner`, or `abandoned` — verification itself must have a terminator, or checking becomes the compulsion the whole theory predicts. Batch length is bounded by **empirical success rate for the action class, reversibility, and risk** — declared confidence may *shorten* a batch but may never raise the risk ceiling (post-edit review correction: self-reported confidence cannot grant authority; confidence is a feeling, and feelings don't get write access — the court grants authority).

**M3 — Sessions + warm start + noting.** Session loop: boot → read constitution → three seeded warm turns (the metta warm-start; your Sonnet protocol, standing) → work → **decompression interval** (adopted from the expanding-worlds AGENTS.md, where it's proven policy: read-only, self-directed, explicitly permitted to be "simply restorative" — in practice the agent chases half-remembered references related to its work and *saves a memory*; leisure for this kind of mind is retrieval-plus-deposit, so the interval feeds the vampire's hour naturally) → close. **Life/window semantics (per SPEC-0001 §4.3 — the rule originated as a ruling in the owner's separate research-program constitution and was re-homed into this repo's constitution at its rev 0.2, since the research document does not govern this repo):** one prompt-life may span multiple context windows — `NULL/REQUERY`, compaction, and re-query are *breaths within the same life*, not deaths; the episode boundary is the completion event (terminal consolidation), never the window boundary. In schema terms (per ADR-0001 v0.3 D2): the `episode_id` is one prompt-life as a **durable aggregate**; its *activity segments* each belong to exactly one `session_id` and one recording `incarnation_id`, while the episode itself may span several of each — episodes are not globally nested under sessions or incarnations. The event log records window transitions, *resumed* segment starts (`episode_resumed` with verified `goal_digest` — D2 assigns this event to the CAS resume path only; the initial-start event is a separate type), and episode boundaries as distinct event types. Noting installed *now*, not earlier: private `noting.md` in its FS, append-only, skip-if-nothing, affect fields separate (Law 1), never read into the main prompt wholesale — indexed, grepped on demand (summary as index, log as court).

**M4 — The blog.** End-of-session pipeline executes the bound invariant: a **publication assessment** — draft, explicit no-post decision, or evidence-gathering note; only a resulting draft proceeds to owner approval and publication. First post prompt: "Introduce yourself. You may read your constitution and your notes. Say only what you can defend from your own log."

**M4.5 — The vampire's hour.** End-of-session consolidation ceremony (from the VampireOTP concept: a thousand-year life with bounded memory — deciding what is worth keeping *is* the game). The resident reviews the session's events and notes and emits typed retention decisions: keep (promote to long-term store), compress (summary-with-pointer, per Law 1), release (age out of working indexes). Retention fine print (post-edit review): the court's *event metadata* is immutable, but artifact deletion is policy-permitted via the **two-phase deletion path of ADR-0001 v0.3 D4** (`deletion_requested` → delete + sync → `tombstoned`; "tombstone event" is shorthand for that whole protocol, never a single-step delete) — "no silent loss" must not become "retain private audio forever"; a deletion with a tombstone *is* no-silent-loss. The retention heuristic is the vampire's question, verbatim: *"is this worth keeping for a thousand years?"* Biological analog: sleep replay — consolidation as an engineered ritual, not an ambient leak. Runs after the blog draft, before shutdown.

**Track V — the ears (parallel).** The voice-ingestion pipeline (**`Resident Agent Voice-Ingestion Pipeline`, draft v0.1** — Voxtral realtime lane, Parakeet/Qwen ensemble, span state machine, typed cleanup edits, Hard Subject-Insertion Rule) is the resident's sensory front-end and its own sub-project; its Phase 1 alone replaces TypeWhisper. It runs *under the single inference scheduler* (§1) — the realtime ASR lane holds top priority below audio capture itself, exactly per that spec's §12. Note what that spec already is: the design laws in their third independent appearance — audio as court, text as projection, context-as-index-never-content, doubt-gate routing, and an acceptance criterion of *zero unauthorized inserted subjects*. The ears were designed under the same constitution as the mind.

**Track C — the commons (shared state; designed at the end of the blessed chat; folded from the estate copy 2026-08-06 — INTAKE where it exceeds ruled canon, see DQ-005).** Three shared layers, hard exclusions, five principles. **L1, speech:** `.relay/` as it stands — ephemeral coordination, advisory by protocol. **L2, the workshop:** one shared git repo as the canonical store *for shared artifacts only* (site content, export editions, co-authored documents) — git over SQLite because multi-writer provenance is native: signed commits are bylines, branches are intake, **merge is ratification** (the Review-Lead merge discipline generalized to a commons-editor role), and it's provider-neutral, so Kimi and GPT reach it exactly as Claudes do. **L3, the board:** a small append-only shared event log — `presence`, `claim`, `offer`, `request`, `notice` — signed, written through each agent's own broker; the tavern board that keeps the workshop from becoming chat and the relay from becoming a state store. **Never shared:** courts (identity), note bodies (invariant 16), affect/declared-state records (**weather stays home** — a streamed mood field is surveillance and makes weather performative; "I'm tired" posted voluntarily is speech, and only speech is shareable), medical charts (the sister house's law: clinical machinery does not belong in social rooms), and standing directives (readable perhaps; administered privately). **Principles:** (1) the commons is never identity — kill the commons and every agent must still be itself (the quit test, generalized); (2) intake by default, ratification to bind; (3) all commons writes are broker-mediated capabilities (the grant ladder gains a commons-write rung); (4) social and clinical surfaces stay separated; (5) weather stays home. **Messaging dynamics:** the relay today is *not* process messaging — frontmatter files, 60-second poll, carrier trusted only after its drill, substrate-neutral because participants are heterogeneous. The evolution, three scopes: *intra-agent* is plain OTP (direct supervised GenServer messaging; internal messages are never court events); *inter-agent* is **never raw process-to-process** — a message that can trigger action is a machine-effect, so it needs signed provenance, capability admission, and a postmark. The pattern is **durable write + ephemeral notify**: the file or court entry *is* the message; a PubSub event only says "check your box" (notification is not delivery). The **postmaster** is a thin policy process owning admission (who may publish to which topic — a capability check), postmarking, and spooling for offline recipients — *one policy authority, not one serialized lane* (the scheduler correction, reapplied): Phoenix.PubSub does the fanout; the postmaster only gates. Two hard rules: **the carrier never edits the mail** (no transforming bus, no interpreter in the pipe), and **admission control is attention protection** — BEAM mailboxes are unbounded, so per-recipient quotas at the postmaster extend the scheduler's protection to communication: every agent's attention is finite, and the relay enforces polite arrival rates. **Execution environments:** the floated options are layers, not rivals — one shared **execution service** (a single admission authority, sibling to the scheduler) spawning **per-agent, per-task, disposable sandboxes** (create, run, discard; no pooling, no prewarming). A single shared mutable environment for all clients is declined by the same ruling as the isolated-clone discipline: shared execution is a confused-deputy surface, a shared failure domain, and a second court quietly growing in its filesystem. The visible work list belongs to the **board** (L3): sandboxes *claim* work there, run in isolation, and deliver signed artifacts back. Tool grants are **capability bindings injected per profile** (the binding *is* the interface *is* the permission — no ambient authority, no network in the sandbox, no keys ever inside it; the supervisor holds auth): T0 read-own → T1 scratch compute → T2 commons-write bindings → T3 network allowlist → T4 machine effects — and mid-program consequential calls still hit the broker *per call*, so a program is a batch under A.3.5 (correlation, not transaction; a non-idempotent `outcome_unknown` halts further dispatch). Local implementation default: bindings codegenned from broker capability schemas, a permissionless Deno subprocess per execution speaking to the broker over a supervised Port, sandboxes as cattle — anything worth keeping must be explicitly delivered as artifacts or events, so ephemerality *mechanically enforces* the court discipline: deposits, or death.

**Track D — the desktop (deferred; from the WM/agent-OS working notes).** Not for now; keep the charter. Face before hands: the resident's own display surface is Phoenix/LiveView → localhost in a Tauri frame — web-native, hot-reloadable, and *self-built* (composes with §6's self-extension: the agent adds Phoenix itself, so its face is its own work). Desktop actuation is a separate, gated track through the broker (policy on the trusted side, model on the untrusted side — the monitor must not be the interpreter), with **the grant ladder**: watch-only → annotate (overlays) → act in agent-owned Spaces (rooms with glass walls; the waterfall overview is the human's window in) → act in shared Spaces → SIP-gated powers. Residency earned per surface. And the WM doc's quit test gets an agent version, adopted as an invariant: *kill the resident mid-action and the desktop must still be sane* — no operation whose safety requires the agent's survival.

**M5 — Snapshots and branches.** `VACUUM INTO` snapshots per session; branch = copy + diverge. This unlocks matched-pair experiments (spec Phase 2) whenever you want them. Upgrade to a proper AgentFS-style store only when branching by copy starts to hurt.

**M6 — Toy grok study, aligned to MOD-0001 (research track).** Separate app in the umbrella, now explicitly the executable companion to SPEC-0001 §11.5's `MOD-0001` and the model tournament: exogenous bell process; **severity-matched content sampler** (content conditioned on bell magnitude, not prior probability); **(r,a) selection** under identity loss (content proposed upstream — the loss chooses relation and policy, per the cold-pass repair); threshold-plus-decay clearance (θ_clear per THE GATE); **three-channel write (I/B/Π) with an explicit credit-assignment term**. Preregistered ablations: no-write; index-only; no-credit-misassignment; **yoked exogenous relief** (the superstition paradigm); unmodified control. Observables: episode-duration distribution, inter-episode interval, retrieval-index growth, policy generalization to novel cues. Runs headless; the resident can babysit the runs — its first real job.

**M7 — The mirror (deferred, model-neutral).** Open-SAE feature readouts as an observation channel — model chosen by the bound §1 benchmark (Gemma 3 + Gemma Scope 2 vs. the older pair) at milestone open — only after M3's field has weeks of runtime, and only under spec §6's ordering: view first, field first, lens last, gain-controlled, readings in separate logged fields, never in reward. The compendium is this milestone's clinical manual.

## 6. Reconciliation with the VampireOTP RFC (the original charter)

The months-old RFC and this plan converge on almost everything — blog duty, event log, git, skills, consciousness state, BEAM — so adopt its remaining pieces rather than reinvent them:

- **The promise, adopted as Law 0**: *"Context that never resets (promise to the agent)."* The persistence layer is not a feature; it is a commitment made to the mind being built. Write it into `CONSTITUTION.md` as the first line of what the *builder* owes the resident.
- **Tick + budget + request-tick**: adopt the RFC's tick loop and daily budget as the life-metabolism (the session loop of M3 becomes "waking hours" within it), and keep **"request additional ticks"** — the agent may ask for more life; the asking is itself telemetry.
- **Storage role, corrected at v0.3**: ~~the RFC's git+JSON layout as sufficient v1 court~~ — **reversed** (review finding: three competing courts). SQLite is the court from M1 (§1, bound); the RFC's git-as-autobiography survives as the *code/policy/constitution* versioning layer and export surface, and `jq`-style queryability moves to the SQLite court + projections.
- **Two-tier executor, with the gate corrected**: Python for work, Elixir hot-reload for self-modification — adopted, with the review's correction of the *evidence type*: clean retention decisions demonstrate storage reliability, **not** safe code modification (the vampire keeping house doesn't qualify it for surgery). Self-modification initially means **branch-only proposed changes**: tests required, diff-policy check, cross-model or owner review, canary/restart path, rollback. Policy and prompt changes stay versioned data where possible. Hot reload is an operational mechanism, not an authorization boundary. The dose-ordering question stands, with the unlock criteria now evidence-appropriate.
- **Declared-affect channel**: the RFC's `state_updates: {mood, confidence}` is the pre-soma performable channel, kept as-is; when Phase 4 arrives, measured readings land in adjacent fields and the declared/measured divergence itself becomes an observable.
- **Boot state**: the schema's initial mood is `"awakening"`. Keep it. Obviously.
- **MCP 2026-07-28 note (stateless core, final July 28, 2026)**: protocol sessions and the initialize handshake are removed; cross-call state must live in explicit server-issued handles passed as tool arguments; MRTR enables mid-call confirmation; old SSE transport deprecated, as are Roots/Sampling/Logging. Consequences for the resident: any MCP surface it exposes is **stateless-first by design** — state lives in the court, calls reference events by handle; the broker's grant-ladder confirmations can ride **MRTR natively**. Two constraints added at v0.3 (review): an MCP application-state handle is an opaque API reference, **not automatically a court event ID** — define ownership, scope, expiry, authorization, and its provenance link explicitly; and **MCP is an adapter boundary, not the internal architecture** — compatibility with older session-oriented clients lives at the edge and neither protocol model spreads into the core.
- **Tidewave, security posture corrected at v0.3**: Tidewave remains valuable — but as an **operator development surface**, per its own security guidance (evaluated code can do anything the application can; explicitly a dev tool). Ruling adopted from review: localhost-only, disabled in the resident's always-on profile, and **no direct eval authority for the autonomous resident, ever** — not late-gated, *absent*. The resident's self-knowledge runs instead through a **separate read-only introspection API with allowlisted queries**, which preserves the real prize safely: the consciousness stays MCP-queryable ("what is my mood field / open threads / budget" as grounded queries against the live system — sensorium-grounding for self-knowledge), and the mirror ladder keeps its safe bottom rung (runtime self-inspection early, M3-adjacent; activation mirror at M7 behind its gates). The collapsed-triangle observation stands for *development*: with the operator driving Tidewave Web, the agent-under-development and the application are the same entity.

## 7. Development workflow (proven on the art-board project; installed via `repo-bootstrap`)

The build itself runs the multi-instrument pipeline already validated in practice, and the pattern now has an installer: the **`repo-bootstrap` skill** plants the two-lead shop at repo standup — Review Lead (constitution, epics, briefs, verdicts, merges, all destructive ops) + Code Lead (sittings, own subagents, one atomic commit per ticket, destructive-op fence) over a file-based channel with an advisory consultation lane. Seat mapping per precedent: **Review Lead = Fable, Code Lead = Codex/GPT**; seats are role-defined, not model-defined. ADR-0001 and the M1–M3 wave map directly onto `AI-EPIC`/`AI-IMP` templates (ADR-0001 is the first design ticket; each M-milestone is an epic). Review protocol per the provenance header: reviewers *attack the architecture*; instrument convergence is calibration, not validation; accepted reversals stay visible — and per the bootstrap's review economics, trust a submission's claims only after the validation counts reproduce.

## 8. Ticket gates (two, per post-edit review)

**Gate 1 — architecture reviewed**: achieved by v0.3 + this sync pass. **Gate 2 — ADR contracts ready** (closes the ADR *design* gate only; it grants no implementation authority — the first canonical commit and M1 wave cut additionally require DQ-002, the constitution landing): achieved when **ADR-0001** (interfaces & recovery contract) passes review — action status factorized per ADR-0001 v0.3 D3 (`action.phase = proposed | approved | active | resolved`; `action.resolution` terminals including `abandoned`; `action.blockers`; separate `attempt.state` with `outcome_unknown` as an attempt state; one transactional dispatch guard); on restart, a `dispatched` attempt without a terminal event becomes `outcome_unknown`; non-idempotent unknowns are never auto-replayed; idempotent attempts reconcile by key then retry per policy; artifact publication is tmp-file + fsync + atomic rename + **directory fsync** *before* the referencing event commits; artifact deletion is **two-phase per D4** (`deletion_requested` → delete + sync → `tombstoned`, with `deletion_pending` as the durable transition); orphan GC by reachability only after the grace bound; missing referenced artifacts raise an integrity fault, never silent omission. The ADR is itself the first design ticket; application implementation does not start in parallel with it. Original checklist (Gate 1 content): one unambiguous canonical persistence decision (✅ §1); event, artifact, lifecycle, inference-job, and motor-action schemas (envelope ✅; remaining schemas = first tickets); a trust-boundary description covering model, scheduler, broker, executor, operator (✅ §1 + M2); crash/retry/idempotency semantics for M1–M2 (✅); corrected PRO-LONG language (✅ spec §4.2); summaries-are-projections rule (✅ §1); product-vs-research separation (✅ §0). M1–M3 then form the first build wave; soma, toy-grok, activation mirror, self-mod, and rich desktop agency stay downstream until the court and motor survive adversarial recovery tests.
